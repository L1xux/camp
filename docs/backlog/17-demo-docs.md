# [D5] 데모 시나리오 리허설 + README, RUNBOOK, 운영 문서 정비

라벨: `D5` / 마일스톤: D5 / 선행: 09, 10, 13, 15, 16 (시연 대상 기능 전부)

## 배경 / 해결하려는 문제

기능이 전부 있어도 "처음부터 끝까지 한 번에 재현"이 안 되면 시연도 검증도 실패한다.
초기화된 환경에서 문서의 절차만 따라 전체 흐름이 재현되는지 리허설로 확인하고,
그 절차 자체를 README로 만든다. 이 레포를 처음 보는 사람의 진입점이 README인데
현재 빈 파일이다. 운영 절차(재기동, 롤백, 시크릿 교체)도 문서가 없으면 매번
기억에 의존하게 된다.

## 요구사항

**데모 시나리오 (`docs/demo-script.md`)**
- 전체 흐름 대본:
  1. 마케터: 캠페인 생성 → 후보 담기 → 확정 → 계약 상신 (결재선 자동 생성 확인)
  2. 역할 전환 → 팀장 승인 → 본부장 승인 → 계약 ACTIVE, 예산 차감 화면 확인
  3. 배치 수동 트리거 → 대시보드 수치 갱신 확인
  4. AI 질의: "이번 시즌 X브랜드 캠페인 ROI 상위 5명은?" → 도구 호출 → 차트 + 근거 답변
  5. 같은 질의를 Claude Desktop에서 → 동일 동작. 권한 침해 질의 1건 → 차단 사유 표시
- 각 단계의 사전 조건과 확인 포인트 명시
- AI 질의는 비결정성에 대비해 백업 질의 2개 준비
- **리허설 2회**: 완전 초기화 상태(`docker compose down -v`)에서 문서 절차만으로
  환경 구성 → 시드 → 데모 완주. 소요 시간과 발견된 문제를 기록

**스모크 테스트**
- 자동화 2종: ① 헬스 체크 + 캠페인 생성 → 조회 왕복, ② AI 질의 1건 완주 (이벤트 done 수신)
- 단일 명령 실행 — 재기동, 배포 직후의 기본 확인 수단

**README.md (현재 빈 파일)**
- 프로젝트 소개: 어떤 문제를 왜 푸는가 (3문단 이내)
- 아키텍처: 모듈 구성도, 요청/배치/AI 질의의 데이터 흐름
- 품질 지표 현황: 골든셋 점수, 성능 측정치 (이슈 12, 16의 결과 수치)
- 실행 방법: 요구 도구 → compose 기동 → 시드 → 앱 실행 → 화면 접속, 순서대로
- Claude Desktop 연동 절차 (이슈 13의 문서를 정리해 포함)
- 문서 지도: PLAN, ADR 목록, METRICS, RUNBOOK 링크와 각 한 줄 설명

**RUNBOOK.md**
- 기동/재기동 절차, 시드 재실행, 롤백 절차(직전 태그로 되돌리기),
  시크릿 유출 시 폐기와 재발급 순서, DB 백업과 복구 (로컬 볼륨 기준)
- 각 절차는 복사해서 실행 가능한 명령 블록으로

**운영 문서 개시**
- `docs/ops-log.md`: 배포성 이벤트 기록 시작 (D1~D5 소급 포함),
  특이사항은 Issue 번호로 연결하는 규칙 명시
- `docs/METRICS.md`: 품질 지표 7종(골든셋 정확도, 차단률, 첫 토큰 지연, 질의 비용,
  배치 처리량, 조회 지연, 에러율)을 정의 / 수집 방법 / 목표 / 확인 주기 표로
- CHANGELOG 자동 생성 설정 (git-cliff), `v0.1.0` 태그
- 스프린트 회고 `docs/retro/2026-08-sprint-01.md`: 지표 대비 목표 표,
  Keep/Problem/Try, Backlog 재조정 결정
