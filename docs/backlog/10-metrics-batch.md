# [D3] 성과 수집 배치 — 수집 포트 정의, 시뮬레이터 어댑터, 일별 스냅샷 적재

라벨: `D3`, `mvp` / 마일스톤: D3 / 선행: 02 (DB), 06 (채널 데이터)

## 배경 / 해결하려는 문제

캠페인 성과(조회수, 좋아요 등)가 매일 쌓여야 대시보드와 AI 질의의 재료가 생긴다.
인스타그램은 본인 OAuth 동의 없이 API 수집이 불가능해 시뮬레이터로 대체하고,
유튜브는 실제 API(이슈 11)로 수집한다. 따라서 "수집기"를 인터페이스(포트)로 추상화하고
플랫폼별 구현(어댑터)을 갈아끼우는 구조가 필수다 — 향후 인스타그램 정식 연동 시
어댑터 하나만 추가하면 되는 구조임을 코드로 증명한다.
배치는 채널 한 건의 실패가 전체 실행을 중단시키지 않아야 한다.

## 요구사항

**수집 포트 (application 모듈)**
- `MetricsCollector` 인터페이스: 입력 채널 목록 → 채널별 일 성과
  (조회수, 좋아요 수, 댓글 수, 팔로워/구독자 수)
- 시그니처는 플랫폼 중립 — 특정 플랫폼의 API 형태가 인터페이스에 노출되면 안 된다
  (이슈 11의 YouTube 구현이 시그니처 변경 없이 꽂히는 것이 설계 검증 기준)
- 어댑터 라우팅: 채널의 플랫폼 값으로 구현체 선택 (INSTAGRAM → 시뮬레이터,
  YOUTUBE → 설정에 따라 실API 또는 시뮬레이터)

**시뮬레이터 어댑터**
- 채널 규모(팔로워 수)에 비례한 일 성과 생성: 성장 추세 + 요일 효과 + 노이즈.
  완전 난수는 금지 — "ROI 상위 5명" 같은 질의의 답이 안정적으로 존재해야
  이후 골든셋 평가(이슈 16)의 기대값을 고정할 수 있다
- 난수 시드 고정: 같은 채널 + 같은 날짜 = 항상 같은 값 (결정적 생성)

**배치 실행**
- 스케줄 실행(매일 04:00 KST) + 수동 트리거 API `POST /api/admin/batch/metrics-collection`
- 처리 흐름: 수집 대상 채널 조회 → 어댑터 호출 → `MetricSnapshot` 벌크 적재 →
  캠페인 단위 집계 갱신
- **건별 실패 격리**: 채널 1건의 수집/저장 실패는 기록 후 다음 건 진행.
  실행 종료 시 요약(대상, 성공, 실패, 소요 시간)을 로그 + 배치 실행 이력 테이블에 기록
- **멱등성**: 같은 날짜 재실행 시 스냅샷을 중복 삽입하지 않고 갱신
  (채널 ID + 날짜 유니크 제약 + MERGE/upsert)
- **동시 실행 방지**: 실행 중 재트리거는 거부 (실행 이력 테이블의 RUNNING 상태 또는
  DB 잠금으로 상호 배제)
- **성능**: 벌크 삽입은 JDBC batch(또는 동급)로 — 건별 INSERT 왕복 금지.
  10만 행 기준 5분 이내, 측정치를 PR에 기록

## 예외 케이스

- [ ] 채널 1건 수집 실패 → 해당 건 실패 기록, 배치 계속, 요약에 실패 1 집계
- [ ] 전 건 실패 (어댑터 전체 장애) → 배치 실행을 실패로 마감, 에러 트래킹에 이벤트 1건
- [ ] 같은 날짜 2회 실행 → 스냅샷 행 수 불변 (갱신만)
- [ ] 실행 중 수동 재트리거 → 409 + "실행 중" 응답
- [ ] 수집 대상 채널 0건 → 성공으로 종료 (성공 0, 실패 0), 오류 아님
- [ ] 집계 갱신 단계 실패 → 적재된 스냅샷은 유효하게 남고, 집계만 재실행 가능
- [ ] 배치 프로세스가 도중에 죽음(강제 종료) → 실행 이력이 RUNNING으로 남는 문제:
      다음 실행 시 stale RUNNING 판정 기준(타임아웃)과 처리 방침 정의
- [ ] 미래 날짜, 캠페인 기간 밖 날짜 수집 요청 → 거부 또는 무시 (동작 정의)

## 테스트 케이스

**단위**
- [ ] 시뮬레이터 결정성: 같은 채널 + 같은 날짜 2회 호출 → 동일 값
- [ ] 시뮬레이터 분포: 팔로워 10배 채널의 평균 조회수가 유의미하게 큼 (비율 검증)
- [ ] 어댑터 라우팅: 플랫폼 값별 구현체 선택 확인
- [ ] 배치 요약 집계 로직: 성공/실패 혼합 입력 → 요약 수치 정확

**통합 (실제 Oracle)**
- [ ] 채널 100건 수집 → 스냅샷 100행, 캠페인 집계 갱신 확인
- [ ] 3번째 채널에서 예외를 던지는 모의 어댑터 → 99행 적재 + 실패 1 기록 + 배치 성공 종료
- [ ] 같은 날짜 재실행 → 행 수 동일, 값 갱신 확인
- [ ] 유니크 제약: 같은 채널 + 같은 날짜 중복 INSERT 시도 → 제약 위반 (스키마 검증)
- [ ] 동시 트리거 2건 → 1건 실행, 1건 409
- [ ] 수동 트리거 → 실행 이력 테이블에 시작/종료/요약 기록

**성능**
- [ ] 10만 행 벌크 적재 소요 시간 측정 → 5분 이내, 수치를 PR에 기록
- [ ] 건별 INSERT 대비 벌크 방식의 시간 비교 1회 기록 (벌크 선택의 근거)

## 완료 조건

- [ ] 수동 트리거 한 번으로 수집 → 적재 → 집계 → 대시보드 수치 변화가 재현
- [ ] 실패 격리, 멱등성, 상호 배제가 각각 테스트로 증명됨
- [ ] 포트 시그니처에 플랫폼 종속 없음 (이슈 11에서 무변경으로 구현 추가되는지가 최종 검증)
