# [D3] 대용량 시드 데이터 생성 + 조회 성능 튜닝 (파티셔닝, 인덱스, 실행계획)

라벨: `D3`, `mvp`, `cuttable` / 마일스톤: D3 / 선행: 02 (DB), 05~08 (도메인과 운영 기능), 10 (시뮬레이터)
축소 우선순위 1 — 시드와 기본 인덱스는 유지, 파티셔닝과 심화 튜닝만 보류 가능

## 배경 / 해결하려는 문제

일별 성과 스냅샷은 3년치 수백만 행 규모다. 이 크기에서 대시보드 조회가 500ms 이내로
동작하려면 인덱스와 파티셔닝 설계가 필요하고, 그 설계가 맞는지는 실행계획과 측정으로만
증명된다. 또한 AI Text-to-SQL(이슈 13)이 때리는 것도 같은 테이블이므로, 여기가 느리면
AI 응답 전체가 느려진다. 시드 데이터는 난수 시드를 고정해 재현 가능해야 한다 —
골든셋 평가(이슈 16)의 기대값("ROI 1위는 누구")이 실행마다 바뀌면 평가가 불가능하다.

## 요구사항

**시드 데이터 생성**
- 규모: 브랜드 3~5개, 인플루언서 수천 명(각 채널 1~3개), 캠페인 수백 건
  (상태 분포: SETTLED 다수 + 진행 중 소수), 계약과 결재 이력, 3년치 일별 스냅샷 수백만 행
- 결정적 생성: 난수 시드 고정 — 같은 스크립트 실행 = 같은 데이터
- 생성 로직은 시뮬레이터(이슈 10)와 공유 — 시드 데이터와 배치 신규 데이터의 분포가
  달라지면 통계가 단절된다
- 도메인 규칙 준수: 예산 초과 계약, 불법 상태 조합이 시드에 존재하면 안 된다
  (시드도 도메인 검증 로직을 통과시켜 생성)
- 실행: 단일 명령, 완료 시 규모 요약 출력, 소요 시간 기록
- 재실행 방식 명시: 전체 초기화 후 재생성 (부분 재개는 만들지 않는다 — 복잡도 대비 이득 없음)

**조회 성능 튜닝**
- 대상 쿼리 3종 (운영 화면과 AI 질의가 실제로 실행하는 형태):
  1. 캠페인 대시보드: 특정 캠페인의 기간 내 일별 집계 시계열
  2. 성과 순위: 시즌 + 카테고리 조건으로 인플루언서 ROI 상위 N
  3. 채널 추이: 채널 1개의 기간 시계열
- 스냅샷 테이블: 날짜 기준 레인지 파티셔닝(월 단위), 파티션 프루닝이 실행계획에서
  확인되어야 함
- 인덱스 설계: 대상 쿼리의 접근 경로 기준. 각 인덱스의 존재 이유를 주석으로
  (근거 없는 인덱스는 쓰기 비용만 늘린다)
- 절차: 튜닝 전 측정 → `EXPLAIN PLAN` 확인 → 인덱스/파티셔닝 적용 → 재측정 —
  전/후 비교표(쿼리별 p50/p95)를 PR에 첨부
- 옵티마이저 통계 갱신을 시딩 마지막 단계에 포함 (통계 없는 대용량 테이블은
  실행계획이 엉뚱하게 잡힌다)
- 목표: 대상 쿼리 3종 p95 ≤ 500ms

## 예외 케이스

- [ ] 시드 실행 도중 실패 → 전체 초기화 후 재실행으로 복구 (절차를 스크립트 도움말에 명시)
- [ ] 시드 데이터의 도메인 규칙 위반 → 생성 완료 후 검증 단계에서 실패로 처리
      (침묵 통과 금지)
- [ ] 파티션 범위 밖 날짜(3년 이전, 미래) 삽입 → 최대값 파티션 또는 자동 생성
      (INTERVAL 파티셔닝) 중 택일, 선택을 마이그레이션 주석에 기록
- [ ] 시드 후 통계 미갱신 상태 → 대상 쿼리가 풀스캔으로 잡히는 것을 확인하고
      통계 갱신 후 재확인 (통계의 효과를 기록으로 남김)

## 테스트 케이스

**시드 검증**
- [ ] 같은 시드로 2회 생성 → 주요 테이블 행 수와 체크섬 동일 (재현성)
- [ ] 규모 검증: 스냅샷 행 수 ≥ 목표치, 캠페인 상태 분포가 설계 비율 ±10% 이내
- [ ] 무결성 검증 쿼리: 예산 초과 계약 0건, 불법 상태 조합 0건, 고아 레코드
      (캠페인 없는 계약 등) 0건
- [ ] 시드 위에서 이슈 06~08의 통합 테스트 스위트 그린 (대용량과 기능의 공존 확인)

**성능 검증 (측정 스크립트로 자동화, 결과는 표로 출력)**
- [ ] 대상 쿼리 3종 각 20회 실행 → p50/p95 산출, 튜닝 전/후 2회 측정
- [ ] 실행계획 검증: 쿼리 1과 3에서 파티션 프루닝 동작 (접근 파티션 수 확인)
- [ ] 실행계획 검증: 풀스캔이 남아 있는 쿼리가 없는지 확인, 의도된 풀스캔이면 사유 기록
- [ ] 인덱스 사용 확인: 각 대상 쿼리가 설계된 인덱스를 타는지 실행계획으로 대조
- [ ] 회귀 방지: 측정 스크립트를 레포에 남겨 이후 스키마 변경 시 재실행 가능하게

## 완료 조건

- [ ] 단일 명령으로 수백만 행 시드 재현, 소요 시간 기록
- [ ] 튜닝 전/후 측정표와 실행계획이 PR에 첨부됨
- [ ] p95 ≤ 500ms 달성, 미달 항목은 사유와 후속 이슈 번호 명시

## 보류 기준

D3 종료 시점에 시간이 부족하면: 시드 생성과 기본 인덱스까지는 완료하고,
파티셔닝과 실행계획 심화 분석만 후속 이슈로 분리한다. 이 경우에도 "튜닝 전" 측정표는
남긴다 — 다음 작업의 기준선이 된다.
