# [D4] 하이브리드 문서 검색 (RAG) — 벡터 + 키워드, 브랜드 필터 선적용

라벨: `D4`, `mvp`, `cuttable` / 마일스톤: D4 / 선행: 02 (Oracle 23ai), 04 (관측), 07 (브랜드 격리)
축소 우선순위 3 — 기능은 유지, 문서 코퍼스 규모만 축소 가능

## 배경 / 해결하려는 문제

"작년 F/W에 누가 잘했나"는 SQL이 답하지만, "왜 그 캠페인이 잘됐나"의 근거는
결산 보고서와 브랜드 가이드라인 같은 비정형 문서에 있다. 문서를 벡터 임베딩과
키워드 인덱스로 저장하고, 질의 시 두 방식을 병행 검색해 병합하는 하이브리드 검색을
구축한다. 벡터 검색은 의미가 비슷한 문장(다른 표현)을 잡고, 키워드 검색은 고유명사와
정확한 용어를 잡는다 — 한쪽만으로는 둘 중 하나를 놓친다.
저장소는 별도 벡터 DB 없이 Oracle 23ai의 VECTOR 타입과 Oracle Text를 사용한다
(운영 인프라 1개 유지가 선정 이유 — ADR-001).
브랜드 권한 필터는 검색 **전에** 적용한다 — 검색 결과에서 걸러내는 방식은 타 브랜드
문서가 후보에 올랐다는 것 자체가 이미 권한 위반이다.

## 요구사항

**문서 코퍼스 (가상 데이터, 재현 가능)**
- 브랜드 가이드라인 2부, 표준 계약 조항과 개별 특약, 시즌별 캠페인 결산 보고서 10여 부
- 모든 문서에 메타데이터 필수: `brand_id` (전사 공통 문서는 명시적 NULL = 전 브랜드 조회 가능),
  문서 유형, 시즌
- 정적 파일 + 인제스트 스크립트로 재현 가능하게

**인제스트 파이프라인**
- 청킹: 문단 경계 기준, 청크 크기와 오버랩을 설정값으로 (값과 선정 근거를 코드 주석에)
- 임베딩 생성 → Oracle VECTOR 컬럼 저장, 원문과 메타데이터 동반 저장
- Oracle Text 인덱스 병행 구축 (키워드 검색용)
- 멱등성: 문서 내용 해시 기준 — 같은 문서 재인제스트 시 중복 생성 없음,
  내용이 바뀐 문서는 기존 청크 삭제 후 재생성
- 임베딩 모델명과 차원을 설정으로 관리, 모델 변경 시 전체 재인제스트 절차를 문서화

**하이브리드 검색**
- 입력: 질의 텍스트 + 호출자 브랜드 → 출력: 관련 청크 목록 (원문, 문서명, 위치, 점수)
- 벡터 유사도 검색과 키워드 검색을 각각 실행 후 병합 — 병합 방식은
  RRF(Reciprocal Rank Fusion) 또는 가중 합 중 택일, 선택 근거를 PR에 기록
- **브랜드 필터를 양쪽 검색의 WHERE 조건으로 선적용** (후처리 필터링 금지)
- 결과 0건이면 "관련 문서 없음"을 명시적 신호로 반환 — 답변 합성(이슈 15)이
  이 신호를 받아 "없다"고 답해야 하고, LLM이 지어내면 안 된다
- 검색 실행을 관측 trace의 하위 span으로 기록 (검색 지연과 생성 지연의 분리 측정)

**임베딩 API 장애 시 동작**
- 질의 시점 임베딩 실패 → 키워드 검색 단독으로 폴백하되, 응답에
  "키워드 검색만 사용됨"을 표기 (조용한 품질 저하 금지)
- 인제스트 시점 실패 → 해당 문서 스킵 + 기록, 나머지 진행

## 예외 케이스

- [ ] 타 브랜드 문서가 의미적으로 최고 매치여도 결과에 미포함 (선적용 필터 증명)
- [ ] 전사 공통 문서(brand_id NULL)는 모든 브랜드 질의에서 검색 가능
- [ ] 검색 결과 0건 → 명시적 "없음" 신호 (빈 배열과 구분되는 상태 표기)
- [ ] 무의미한 질의 (`ㅁㄴㅇㄹ`, 공백) → 0건 정상 처리, 예외 없음
- [ ] 임베딩 차원 불일치 (모델 교체 후 재인제스트 누락) → 기동 시 검증으로 조기 실패
- [ ] 같은 문서 재인제스트 → 청크 수 불변
- [ ] 문서 내용 수정 후 재인제스트 → 구 청크 잔존 없음 (검색에 구버전 미노출)
- [ ] 초장문 질의 (토큰 한도 초과) → 잘라내고 처리 또는 400, 동작 정의

## 테스트 케이스

**인제스트**
- [ ] 코퍼스 전체 인제스트 → 문서 수, 청크 수, 임베딩 수 정합
- [ ] 멱등: 같은 코퍼스 2회 인제스트 → 청크 수 동일
- [ ] 갱신: 문서 1부 수정 후 재인제스트 → 해당 문서 청크만 교체, 구버전 검색 미노출
- [ ] 임베딩 실패 주입 (모의 클라이언트) → 해당 문서 스킵 기록, 나머지 정상

**검색 정확성**
- [ ] 키워드형 질의 (보고서 속 고유명사) → 해당 문서 청크가 상위
- [ ] 의미형 질의 (보고서 문장의 패러프레이즈) → 해당 문서 청크가 상위
- [ ] 위 두 케이스로 하이브리드가 단독 방식보다 나음을 확인 (벡터 단독은 고유명사를,
      키워드 단독은 패러프레이즈를 놓치는 것을 각각 확인)
- [ ] 결과에 문서명과 위치 포함 (출처 표기의 재료)

**권한**
- [ ] 브랜드 A 질의 → 브랜드 B 문서 0건 (B 문서와 의미상 유사한 질의로)
- [ ] 브랜드 A 질의 → 전사 공통 문서는 포함
- [ ] 실행된 검색 SQL에 브랜드 조건이 포함되는지 확인 (선적용 증명 — 후처리가 아니라)

**장애 동작**
- [ ] 질의 시 임베딩 실패 → 키워드 단독 결과 + 폴백 표기
- [ ] 검색 0건 → "없음" 신호 반환

## 완료 조건

- [ ] 인제스트 → 검색 → 출처 있는 결과의 전 과정이 스크립트로 재현 가능
- [ ] 브랜드 필터 선적용이 테스트로 증명됨
- [ ] 검색 span이 trace에 분리 기록됨

## 보류 기준

D4 종료 시점에 미완이면 코퍼스를 결산 보고서 3부로 줄인다. 인제스트와 검색 자체는
유지한다 — 기능을 자르는 것이 아니라 재료를 줄인다.
