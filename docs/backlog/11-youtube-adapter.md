# [D3] YouTube Data API 수집 어댑터 — 실제 공개 통계 연동

라벨: `D3`, `mvp`, `cuttable` / 마일스톤: D3 / 선행: 10 (수집 포트)
축소 우선순위 2 — 시간 부족 시 이 이슈를 보류하고 시뮬레이터로 대체

## 배경 / 해결하려는 문제

수집 구조가 "포트와 어댑터"라는 주장을 실제 외부 API 연동으로 증명하는 이슈다.
YouTube Data API v3는 API 키만으로 채널 공개 통계를 조회할 수 있어(사용자 OAuth 불요)
개인 개발자가 실연동 가능한 유일한 대상이다. 실존 채널 몇 개를 등록해 실제 데이터가
배치로 흘러 들어오는 것을 보인다. 저장하는 것은 공개 통계뿐이다.

## 요구사항

- 이슈 10의 `MetricsCollector` 인터페이스 구현체 — **인터페이스 수정 없이** 추가되어야
  한다. 수정이 필요하다면 이슈 10의 추상화 실패이므로 그쪽을 먼저 고친다
- YouTube Data API v3 `channels.list` (part=statistics): 구독자 수, 총 조회수 조회
- 요청 배칭: 채널 ID를 콤마로 묶어 1회 호출에 최대 50개 — 쿼터 소모 절감
  (일 무료 쿼터 10,000 유닛, channels.list는 호출당 1 유닛)
- API 키는 환경변수 주입만. 코드, 설정 파일, 레포 어디에도 키가 존재하면 안 됨
- HTTP 클라이언트는 공통 정책 모듈(이슈 04) 경유: 타임아웃, 지수 백오프 재시도 최대 2회
- 쿼터 소진(HTTP 403, reason=quotaExceeded)은 **재시도 금지** — 재시도로 풀리지 않는
  오류를 재시도하면 쿼터만 더 태운다. 해당 실행의 유튜브 채널 전체를 실패 처리하고
  시뮬레이터 대상 채널은 정상 진행
- 실존 채널 3~5개 등록 (공개 통계만 저장)

## 예외 케이스

- [ ] API 키 미설정 → 이 어댑터만 비활성 (기동 시 경고 로그), 배치는 시뮬레이터
      채널만으로 정상 실행
- [ ] 쿼터 소진 403 → 재시도 없이 실패 분류, 배치 요약에 사유 표기
- [ ] 존재하지 않는 채널 ID (삭제된 채널, 오타) → API가 빈 items 반환 → 해당 건 실패
      기록, 나머지 진행
- [ ] 통계 비공개 채널 (statistics 필드 누락) → 해당 건 스킵 + 사유 기록,
      임의 기본값(0) 저장 금지 — 가짜 0이 집계를 오염시킨다
- [ ] 타임아웃, 5xx → 공통 정책대로 재시도 2회 후 실패, 배치 계속
- [ ] 응답 JSON 구조 변경 (필드 누락, 타입 변경) → 파싱 실패를 해당 건 실패로 기록
- [ ] 요청 50개 초과 배칭 시도 → 어댑터 내부에서 50개 단위 분할

## 테스트 케이스

**단위 (모의 HTTP 서버 — WireMock 또는 MockWebServer)**
- [ ] 정상 응답 파싱: statistics → 도메인 성과 값 매핑 정확성
- [ ] 채널 120개 입력 → 3회 호출로 분할 (50 + 50 + 20)
- [ ] 403 quotaExceeded 응답 → 재시도 0회, 전 건 실패 분류
- [ ] 403 기타 사유 (권한) → quotaExceeded와 구분 처리
- [ ] 빈 items 응답 → 요청한 ID 중 응답에 없는 채널을 실패로 식별
      (부분 성공: 50개 요청, 48개 응답 → 2건만 실패)
- [ ] statistics 누락 채널 → 스킵 분류, 저장 호출 없음
- [ ] 500 응답 → 재시도 2회 발생 확인 (모의 서버 호출 횟수 검증) 후 실패
- [ ] read 타임아웃 → 설정 시간 내 실패

**통합**
- [ ] 시뮬레이터 채널 + 유튜브 채널 혼합 배치 1회 → 양쪽 모두 적재, 요약에 어댑터별 집계
- [ ] API 키 미설정 환경에서 배치 → 유튜브 채널은 스킵 사유 기록, 시뮬레이터 채널 정상
