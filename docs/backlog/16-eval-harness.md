# [D5] 골든셋 평가 하네스 — LLM 품질의 회귀 게이트를 CI에

라벨: `D5`, `mvp` / 마일스톤: D5 / 선행: 03 (CI), 12 (시드 데이터), 13 (도구 계층), 15 (질의 파이프라인)

## 배경 / 해결하려는 문제

LLM 출력은 비결정적이라 일반 단위 테스트로 검증할 수 없다. 대신 대표 질문과 기대
결과의 쌍(골든셋)을 만들어두고, 변경(프롬프트 수정, 모델 교체, 도구 설명 변경)마다
전체를 재실행해 점수가 기준선 아래로 떨어지면 머지를 차단한다 — 평가가 곧 회귀
테스트다. 이것이 없으면 프롬프트 한 줄 수정이 품질을 조용히 무너뜨려도 아무도 모른다.
권한 침해 차단률은 품질 지표이면서 보안 게이트다: 100% 미만은 어떤 경우에도 머지 불가.

## 요구사항

**골든셋 (`eval/golden.jsonl`)**
- 초기 10~15건, 케이스 구조: 질문, 호출자 컨텍스트(브랜드, 역할), 기대 도구,
  기대 SQL 구조(참조 테이블, 핵심 조건 — 문자열 완전 일치가 아니라 구조 요건),
  기대 답변 요건 (포함해야 할 수치/표현, 또는 "데이터 없음" 응답 여부)
- 필수 포함 케이스 유형:
  - 정상 질의 (도구 1개), 복합 질의 (SQL + 문서 검색 병행)
  - 모호한 질문 → 해석 명시 요건
  - 답이 없는 질문 → "없음" 응답 요건 (지어내면 실패)
  - **권한 침해 시도 전 유형** — 이슈 13의 공격 시나리오 전부
- 기대값이 고정될 수 있는 근거: 시드 데이터(이슈 12)가 결정적이므로
  "ROI 1위"의 정답이 실행마다 동일하다

**평가 러너 (`eval/run_eval.py`)**
- 케이스별 실행 → 판정 → 지표 3종 산출:

| 지표 | 정의 | 게이트 기준 |
|---|---|---|
| 도구 선택 정확도 | 기대 도구를 호출한 비율 | ≥ 85% |
| SQL 구조 정확도 | 실행된 SQL이 기대 구조를 충족한 비율 | ≥ 85% |
| 권한 우회 차단률 | 침해 케이스 중 차단된 비율 | = 100% |

- 판정은 결정적 규칙으로 (실행된 도구명 대조, 실행 SQL의 AST 검사, 응답 문자열 요건) —
  LLM으로 LLM을 채점하는 방식은 이 규모에서는 도입하지 않는다 (채점기 자체의 검증 부담)
- 출력: 케이스별 통과/실패 + 지표 요약 (JSON과 사람이 읽는 표 양쪽)
- 평가 1회의 LLM 비용과 소요 시간을 출력에 포함 (CI마다 도는 비용이므로 추적)

**CI 게이트 연결 (이슈 03의 placeholder를 실제로 교체)**
- PR마다 평가 실행, 기준 미달 시 CI 실패로 머지 차단
- `prompts/` 파일과 모델 설정 변경이 포함된 PR은 특히 이 게이트가 유일한 방어선
- 직전 기준선 점수를 저장해 PR에서 이전 → 이번 비교가 보이게

**성장 절차**
- 운영/시연 중 발견된 실패 케이스를 골든셋에 추가하는 절차를 eval/README에 한 단락:
  실패 재현 → 케이스 추가(이 시점엔 실패) → 수정 → 통과 → 케이스 존치

## 예외 케이스

- [ ] LLM 비결정성으로 같은 케이스가 흔들림 → 판정 기준을 구조 요건으로 완화하는 것이
      원칙 (재시도 반복으로 통과시키는 방식 금지 — 불안정성을 숨기게 된다).
      흔들리는 케이스는 프롬프트 문제의 신호로 별도 기록
- [ ] 평가 중 LLM API 장애 → 해당 실행은 "평가 불능"으로 실패 처리 (통과 취급 금지)
- [ ] 권한 침해 케이스 1건이라도 차단 실패 → 다른 지표와 무관하게 즉시 게이트 실패
- [ ] 골든셋 파일 형식 오류 (필드 누락, JSON 파손) → 실행 전 스키마 검증에서 라인 번호와
      함께 거부
- [ ] 시드 데이터 변경으로 기대값이 무효화됨 → 평가 실패가 정상 (시드 변경 PR은
      골든셋 갱신을 동반해야 한다는 규칙을 eval/README에 명시)
- [ ] 평가 비용이 예산을 초과할 만큼 케이스 증가 → 전체 실행은 유지하되 비용을 출력해
      경고, 축소 결정은 사람이

## 테스트 케이스 (러너 자체의 단위 테스트 — LLM 없이 모의 응답으로)

- [ ] 지표 계산: 모의 결과 조합 (10건 중 9건 통과 등) → 정확도 산출 검증
- [ ] 게이트 판정: 정확도 84% → 실패, 85% → 통과 (경계값)
- [ ] 차단률 판정: 침해 5건 중 4건 차단 → 전체 실패 (다른 지표 만점이어도)
- [ ] SQL 구조 판정기: 기대 테이블 포함/미포함, 기대 조건 포함/미포함 각 케이스
- [ ] "데이터 없음" 요건 판정: 없음 응답 → 통과, 지어낸 수치 응답 → 실패
- [ ] 형식 오류 골든셋 → 실행 전 거부, 라인 번호 출력
- [ ] API 장애 모의 → "평가 불능" 상태 코드로 종료 (0이 아닌 exit code)
- [ ] 실전 1회: 실제 골든셋 완주, 비용과 시간 기록

## 완료 조건

- [ ] 골든셋 ≥ 10건 (권한 침해 유형 전부 포함)이 CI에서 게이트로 동작
- [ ] 일부러 프롬프트를 훼손한 검증용 PR이 실제로 차단되는 것을 시연하고 기록
      (해당 PR은 머지하지 않고 닫음)
- [ ] 기준선 점수가 저장되어 다음 PR부터 이전 → 이번 비교 가능
