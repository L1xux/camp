# [D2] React 운영 화면 — 인플루언서, 캠페인, 결재함, 역할 전환

라벨: `D2`, `mvp` / 마일스톤: D2 / 선행: 06, 07, 08 (운영 API)

## 배경 / 해결하려는 문제

운영 기능을 사람이 조작할 화면이 없으면 시연도 검증도 API 클라이언트로만 해야 한다.
마케터가 캠페인을 만들고, 팀장과 본부장이 결재하는 흐름을 화면으로 조작 가능하게 한다.
이 프로젝트의 차별화 요소는 백엔드와 AI 계층이므로 화면은 기성 컴포넌트로 빠르게 —
단, 에러 처리와 역할 전환은 이 화면의 1급 요구사항이다 (결재 워크플로우는 역할이
바뀌어야 진행되므로).

## 요구사항

**기술 구성**
- React + TypeScript + Vite, 개발 서버 포트 5280
- 서버 상태는 TanStack Query(또는 동급) 하나로 관리 — 별도 전역 상태 라이브러리 도입 금지
- UI는 기성 컴포넌트 라이브러리 사용, 커스텀 스타일 최소화
- API 클라이언트: 공통 인스턴스에서 `X-Request-Id` 생성 헤더 부착 (백엔드 로그와 연결),
  에러 응답을 공통 형식으로 파싱

**화면 5개**
1. 인플루언서 목록 — 검색 폼(카테고리, 플랫폼, 팔로워 구간, 이름), 페이징 테이블
2. 인플루언서 상세 — 프로필, 채널 목록, 채널 추가 폼
3. 캠페인 목록/상세 — 상태 뱃지, 예산 사용 현황(예산 대비 ACTIVE + 대기 금액),
   후보 담기(활성 인플루언서 검색 선택), 후보 확정, 상태 전이 버튼
   (현재 상태에서 불가능한 전이는 비활성 + 사유 툴팁)
4. 계약 상신 폼 — 확정 후보 선택, 금액 입력과 동시에 **결재선 미리보기**
   (500만 기준으로 1단계/2단계가 바뀌는 것이 보임), 잔여 예산 표시
5. 결재 대기함 — 내 차례 목록, 상세에서 승인/반려(사유 입력 모달), 처리 후 목록 갱신

**역할 전환 (시연과 개발용)**
- 헤더의 역할 스위처: 마케터 / 팀장 / 본부장 전환. 실제 인증 구축은 범위 외이며
  개발용 장치임을 화면에 명시
- 전환 시 서버 상태 캐시 전체 무효화 — 이전 역할의 결재함이 잔상으로 남으면 안 됨

**에러 표면화**
- 백엔드의 400/404/409 응답 메시지를 그대로 표시 — 도메인 예외 메시지(잔여 예산,
  불법 전이 사유)가 곧 사용자 안내 문구다
- 네트워크 실패: 화면 비파괴 에러 표시 + 재시도 버튼
- 변경 요청(mutation) 진행 중 버튼 비활성화 — 서버의 중복 거부(409)와 이중 방어

## 예외 케이스

- [ ] API 서버 다운 상태에서 화면 진입 → 로딩 → 에러 상태 표시, 흰 화면/무한 스피너 금지
- [ ] 결재 승인 더블클릭 → 요청 1회만 발생 (버튼 비활성), 만약 2회 갔어도 409를 정상 처리
- [ ] 역할 전환 직후 → 결재함, 캠페인 목록이 새 역할 기준으로 갱신
- [ ] 목록 0건 → 빈 상태 안내 문구 (빈 테이블 아님)
- [ ] 폼 검증: 금액에 문자 입력, 음수, 빈 값 → 클라이언트 검증 + 서버 400 처리 양쪽
- [ ] 세션 대상 리소스가 처리 도중 변경됨 (다른 역할이 이미 반려) → 409 응답을 안내로 표시,
      목록 갱신
