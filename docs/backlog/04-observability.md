# [D1] 관측 기반 — 구조화 로깅, 에러 트래킹, LLM 트레이싱, 외부 호출 공통 정책

라벨: `D1`, `setup` / 마일스톤: D1 / 선행: 01 (빌드 골격)

## 배경 / 해결하려는 문제

장애가 나면 "이 요청이 어느 단계까지 갔고, 어디서 왜 죽었나"를 로그로 재구성할 수
있어야 한다. LLM 기능은 추가로 "답변이 왜 이상했나, 비용과 지연이 왜 늘었나"를
호출 단위로 추적해야 한다. 이 계측을 기능 개발 전에 깔아야 모든 기능이 처음부터
계측된 상태로 만들어진다 — 나중에 붙이면 반드시 구멍이 생긴다.
외부 API 호출의 타임아웃과 재시도 정책도 공통 모듈로 지금 정한다. 기능마다 따로
정하면 누락되고, 누락된 호출 하나가 스레드를 무한 점유한다.

## 요구사항

**구조화 로깅 (모든 API, 배치, DB 접근 — LLM 전용이 아님)**
- 전 로그 JSON 포맷: `timestamp`, `level`, `event`, `request_id` 필수
- `request_id`: 요청 진입 시 UUID 생성(클라이언트 헤더 `X-Request-Id`가 있으면 수용),
  MDC(Mapped Diagnostic Context)로 전파 — 컨트롤러 → 유스케이스 → 외부 호출까지 동일 값
- 배치는 실행 단위 ID + 처리 건 단위 ID를 로그에 포함
- 마스킹 필터: 개인정보 패턴(전화번호, 이메일)이 로그에 평문 노출되지 않도록 필터 장착

**에러 트래킹 (Sentry)**
- 미처리 예외 자동 수집: 스택 트레이스 + 요청 컨텍스트, `request_id`를 태그로 첨부
- 같은 예외의 그룹핑과 신규 에러 알림 활성화
- DSN 미설정 환경(로컬 기본)에서는 자동 비활성 — 관측 도구 부재가 앱 기동을 막으면 안 됨

**LLM 트레이싱**
- 모든 LLM 호출: 입력/출력, 토큰 수, 비용, 지연시간을 trace로 기록
- RAG 검색(retrieval)은 하위 span으로 분리 — 검색이 느린지 생성이 느린지 구분 가능해야 함
- `request_id`를 trace 속성으로 첨부 (로그 ↔ Sentry ↔ trace 상호 추적)
- 도구 선정: Langfuse Java SDK 지원 수준 확인 후, 미흡하면 Spring AI Observability
  (Micrometer Tracing) + OTLP 수집기로 결정 — 근거를 ADR-003으로 기록

**외부 호출 공통 정책 (공통 모듈, 모든 HTTP 클라이언트가 경유)**
- 명시적 타임아웃 필수: connect / read 각각 설정, 무한 대기 금지
- 재시도: 지수 백오프 최대 2회. 멱등하지 않은 요청(생성 계열)은 재시도 금지
- 최종 실패 처리: 동기 요청은 오류 응답을 그대로 반환(대체 답변 생성 금지),
  배치는 해당 건 실패 기록 후 다음 건 진행
- LLM 일일 비용 상한 $2: 초과 시 AI 질의 기능만 차단, 운영 API는 정상 동작.
  카운터 저장 위치(DB)와 리셋 기준(KST 자정)을 이 이슈에서 확정.
  카운터 조회 실패 시 질의 거부 (안전한 쪽으로 실패)

## 예외 케이스

- [ ] 스레드 전환(virtual thread, 비동기, 배치 워커)에서 MDC 유실 → 전파 데코레이터 적용,
      전환 지점마다 테스트로 확인
- [ ] Sentry 전송 실패 → 앱 동작에 영향 없음 (버퍼링 후 폐기)
- [ ] 트레이싱 백엔드 다운 → LLM 호출은 정상 진행, 계측 실패만 자체 로그
- [ ] 마스킹 필터가 스택 트레이스 내부 문자열은 못 거름 → 예외 메시지에 개인정보를
      넣지 않는 코딩 규칙으로 보완, 리뷰 체크리스트에 반영
- [ ] 비용 카운터 동시 갱신 → 원자적 증가(DB atomic update)로 유실 방지

## 테스트 케이스

**로깅**
- [ ] HTTP 요청 1건 → 컨트롤러, 서비스, (모의)외부 호출 로그가 전부 같은 request_id
- [ ] `X-Request-Id` 헤더 제공 시 그 값 사용, 미제공 시 생성
- [ ] virtual thread에서 실행되는 코드의 로그에도 request_id 유지
- [ ] 배치 처리 로그에 실행 ID + 건 ID 포함
- [ ] 전화번호, 이메일이 든 로그 → 마스킹된 형태로 출력
- [ ] 로그가 유효한 JSON (파서로 전 건 검증)

**에러 트래킹**
- [ ] 의도적 미처리 예외 → Sentry 이벤트 생성, request_id 태그 확인
- [ ] DSN 미설정으로 기동 → 정상 기동, 경고 로그 1건

**외부 호출 정책**
- [ ] read 타임아웃 시나리오(모의 서버 지연) → 설정 시간 내 실패
- [ ] 5xx 응답 → 백오프 간격으로 2회 재시도 후 실패
- [ ] 4xx 응답 → 재시도 없이 즉시 실패
- [ ] 비멱등 요청 실패 → 재시도 0회 확인
- [ ] 비용 상한 도달 상태 → AI 질의 차단 응답, 운영 API 정상
- [ ] 비용 카운터 병렬 증가 100회 → 정확히 100 반영

**트레이싱**
- [ ] 모의 LLM 호출 1건 → trace에 토큰, 지연, request_id 기록
- [ ] retrieval 포함 호출 → 하위 span 분리 확인

## 완료 조건

- [ ] 요청 1건으로 로그 → Sentry → trace가 같은 request_id로 연결됨을 시연
- [ ] LLM 트레이싱 도구 선정이 ADR-003으로 기록됨
- [ ] 외부 호출이 공통 모듈을 우회할 수 없는 구조 (직접 HTTP 클라이언트 생성을
      ArchUnit 또는 리뷰 체크리스트로 차단)
