# [D2] 인플루언서 풀 — 등록, 검색, 프로필, 채널 1:N

라벨: `D2`, `mvp` / 마일스톤: D2 / 선행: 02 (DB), 05 (도메인 모델)

## 배경 / 해결하려는 문제

캠페인에 담을 인플루언서 정보가 현재는 엑셀 대장에 흩어져 있다는 것이 이 제품이
풀려는 문제의 출발점이다. 인플루언서를 구조화된 데이터로 등록하고 조건 검색이
가능한 풀로 만든다. 한 인플루언서가 인스타그램과 유튜브를 동시에 운영하므로
채널은 1:N 관계이고, 이후 성과 수집은 채널 단위로 붙는다.

## 요구사항

**등록, 수정, 조회**
- `POST /api/influencers` — 이름(필수, 1~50자), 카테고리(enum: FASHION, BEAUTY, LIFESTYLE,
  FOOD, TECH), 소속 형태(enum: FREELANCER, AGENCY), 소속사명(AGENCY일 때 필수), 메모(선택)
- `POST /api/influencers/{id}/channels` — 플랫폼(enum: INSTAGRAM, YOUTUBE),
  채널 식별자(핸들 또는 채널 ID, 필수), 팔로워 수(0 이상 정수)
- `PUT /api/influencers/{id}` — 프로필 수정
- `GET /api/influencers/{id}` — 상세 (채널 목록 포함)
- 삭제 대신 비활성화(`DELETE /api/influencers/{id}` → soft delete):
  계약 이력이 있는 인플루언서가 물리 삭제되면 과거 계약, 결재 기록의 참조가 끊긴다.
  비활성 인플루언서는 검색 기본 결과에서 제외되고 신규 캠페인 후보로 담을 수 없지만,
  기존 계약과 이력 화면에서는 계속 조회된다

**검색**
- `GET /api/influencers?category=&platform=&minFollowers=&maxFollowers=&q=&page=&size=&sort=`
- 조건은 전부 선택적, 여러 개 지정 시 AND 결합. `q`는 이름 부분 일치
- `platform` 조건: 해당 플랫폼 채널을 하나라도 가진 인플루언서
- `minFollowers`/`maxFollowers`: 채널 팔로워 합계 기준 (기준을 응답 문서에 명시)
- 페이징 필수(기본 20, 최대 100), 정렬: 팔로워 합계순, 등록일순

**입력 검증**
- Bean Validation으로 요청 DTO 검증, 위반 시 400과 필드별 오류 메시지
- 요청 본문 크기 제한, 페이지 크기 상한 초과는 400 (조용히 잘라내지 않는다)

## 예외 케이스

- [ ] 동일 플랫폼 + 동일 채널 식별자 중복 등록 → 409, 응답에 기존 리소스 ID
- [ ] 존재하지 않는 인플루언서 ID에 채널 추가/수정/조회 → 404
- [ ] AGENCY 선택 + 소속사명 누락 → 400
- [ ] 팔로워 수 음수, 카테고리에 없는 값, 이름 51자 → 각각 400 (필드명 포함 메시지)
- [ ] minFollowers > maxFollowers → 400
- [ ] 비활성 인플루언서 수정 시도 → 409 (재활성화 API는 범위 외, 필요 시 별도 이슈)
- [ ] 검색 조건 전무 → 활성 전체를 페이징으로 반환 (오류 아님)
- [ ] 존재하지 않는 정렬 키 → 400
- [ ] page가 전체 범위를 벗어남 → 빈 목록 + 페이징 메타데이터 (오류 아님)

## 테스트 케이스

**단위 (검증, 매핑)**
- [ ] DTO 필드 검증 전 항목: 이름 누락/공백/51자, 카테고리 오타, 팔로워 −1, 소속사명 조건부 필수
- [ ] soft delete 상태 전이: 활성 → 비활성, 비활성 인플루언서의 수정 거부

**통합 (실제 Oracle, API 계약)**
- [ ] 등록 → 201 + Location 헤더, 상세 조회로 왕복 검증
- [ ] 채널 2개(INSTAGRAM + YOUTUBE) 추가 → 상세에 2건, 팔로워 합계 정확
- [ ] 채널 중복 등록 → 409 (같은 요청 재전송 포함)
- [ ] 서로 다른 인플루언서가 같은 채널 식별자 등록 → 409 (플랫폼 전역 유니크)
- [ ] 검색: 카테고리 단독 / 플랫폼 단독 / 팔로워 구간 단독 / 3개 AND 조합 각각 결과 검증
- [ ] 검색: `q=김` 부분 일치, 한글 이름 정상 동작
- [ ] 페이징: 총 25건에서 page=1,size=20 → 20건, page=2 → 5건, page=3 → 0건 + 메타데이터
- [ ] 정렬: 팔로워 합계 내림차순 순서 검증
- [ ] 비활성화 → 검색 기본 결과에서 제외, ID 직접 조회는 가능(상태 표기)
- [ ] 필수 필드 누락 응답에 필드별 오류 배열 형식 검증 (프론트가 소비하는 계약)
