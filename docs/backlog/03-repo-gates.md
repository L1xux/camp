# [D1] 레포 운영 규칙 — 브랜치 보호, PR/Issue 템플릿, pre-commit, CI

라벨: `D1`, `setup` / 마일스톤: D1 / 선행: 01 (빌드 골격 — CI가 빌드를 실행하므로)

## 배경 / 해결하려는 문제

코드 리뷰, 시크릿 유출 방지, 테스트 통과 같은 검증이 사람의 기억에 의존하면 반드시
누락된다. 브랜치 보호와 CI로 "검증을 통과하지 않은 코드는 main에 들어갈 수 없다"를
시스템으로 강제하고, 템플릿으로 리뷰와 이슈의 최소 품질을 보장한다. 1인 개발이지만
이 관문이 있어야 리뷰 이력, 검증 이력이 레포에 증거로 남는다.

## 요구사항

**브랜치 전략과 보호 규칙**
- `main` 브랜치 보호: 직접 push 금지, Pull Request로만 머지, CI 상태 체크 통과 필수
- 브랜치 네이밍: `feat/{이슈번호}-{요약}`, `fix/{이슈번호}-{요약}`, 머지 후 삭제
- 커밋 메시지: Conventional Commits (`feat:`, `fix:`, `refactor:`, `test:`, `docs:`, `chore:`)
- PR 크기 상한 diff 400줄 — 초과 시 분할. 리뷰 가능한 크기가 품질의 전제

**PR 템플릿** (`.github/PULL_REQUEST_TEMPLATE.md`)
- 변경 내용과 관련 이슈 번호
- 선택한 접근과 버린 대안
- 영향 범위 점검 5항목: API 계약 / DB 스키마와 데이터 / 공유 모듈 / 리소스 사용량 /
  의존성 — 해당 없으면 '없음'으로 명시 (빈칸 금지)
- AI 생성 코드 검증 체크리스트 (diff 전체 읽음, 낯선 API 문서 대조, 예외 케이스 처리
  확인, 시크릿과 개인정보 미노출, 테스트는 요구사항 기준으로 정의됨)
- 리뷰 지적 수용/기각 기록 칸

**Issue 템플릿** (`.github/ISSUE_TEMPLATE/`)
- `feature.md`: 배경, 요구사항, 예외 케이스, 테스트 케이스, 완료 조건
- `bug.md`: 증상(기대 동작 vs 실제 동작), 재현 절차, 단서(request_id, 에러 트래킹 링크,
  발생 환경과 버전), 완료 조건(재현하는 실패 테스트 작성 → 수정 → 테스트 존치)

**커밋 훅과 의존성 관리**
- pre-commit: 포맷터, 린터, gitleaks(시크릿 스캔)
- Dependabot: gradle, github-actions 생태계 주간 스캔
- GitHub secret scanning 활성화

**CI** (`.github/workflows/ci.yml`)
- PR마다 실행: ① 정적 분석(린트) → ② `./gradlew test` (ArchUnit 포함)
- 통합 테스트용 Oracle: Testcontainers 또는 GitHub Actions service container
- 골든셋 평가 단계는 16번 이슈에서 추가 — 지금은 명시적 placeholder 스텝
  (`echo "eval: pending #16"`)으로 자리만 잡는다

## 예외 케이스

      반복되면 통합 테스트를 별도 job으로 분리해 캐시 활용
- [ ] gitleaks 오탐 (테스트 픽스처의 가짜 토큰) → allowlist에 파일 경로와 사유 주석
- [ ] 자동 생성 파일(잠금 파일 등)로 diff 400줄 초과 → 생성 파일임을 PR 본문에 명시,
      수기 코드만으로 상한 판단
- [ ] 브랜치 보호 활성화 후 로컬에서 main에 커밋해버림 → push가 거부되므로
      브랜치를 새로 따서 옮기는 절차를 README 개발 가이드에 기록

## 테스트 케이스 (관문 자체를 검증)

**보호 규칙**
- [ ] main 직접 push → 서버가 거부
- [ ] CI 실패 상태의 PR → 머지 버튼 비활성
- [ ] CI 통과 PR → 머지 가능

**템플릿**
- [ ] 새 PR 생성 화면에 템플릿 자동 로드
- [ ] 새 Issue 생성 시 feature/bug 선택지 표시, 각 양식 로드

**pre-commit**
- [ ] 가짜 API 키(`sk-` 형태) 커밋 시도 → gitleaks가 차단
- [ ] 포맷 위반 파일 커밋 시도 → 포맷터가 수정 또는 거부
- [ ] allowlist에 등록된 픽스처 파일 → 통과

**CI**
- [ ] 린트 위반 코드 PR → 실패
- [ ] 테스트 실패 코드 PR → 실패
- [ ] ArchUnit 위반 코드 PR → 실패
- [ ] 정상 PR → 통과, 소요 시간 기록 (10분 초과 시 최적화 이슈 생성)
