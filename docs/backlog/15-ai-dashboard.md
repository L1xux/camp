# [D4] 대화형 AI 대시보드 — SSE 스트리밍, 도구 호출 오케스트레이션, 동적 차트

라벨: `D4`, `mvp`, `core` / 마일스톤: D4 / 선행: 09 (프론트 골격), 13 (MCP 도구), 14 (문서 검색)

## 배경 / 해결하려는 문제

"이번 시즌 MLB 캠페인 ROI 상위 5명은?"이라고 자연어로 물으면, LLM이 적절한 도구를
골라 호출하고(수치는 SQL, 근거는 문서 검색), 결과에 맞는 차트를 선언하고, 답변을
스트리밍으로 돌려주는 화면이다. 고정된 위젯 배치가 아니라 질문이 화면을 구성한다.
지능은 전부 백엔드 도구 계층(이슈 13)에 있고 프론트는 이벤트 스트림의 소비자다 —
그래서 같은 질문이 Claude Desktop에서도 동일하게 동작한다.

## 요구사항

**백엔드 스트리밍 엔드포인트**
- `POST /api/assistant/query` — Server-Sent Events 응답
- 요청: `{"question": "...", "conversationId": "..."}` — conversationId로 같은 대화의
  이전 질문/답변 맥락 유지 (서버 보관, 세션 수명 정도면 충분 — 장기 저장은 범위 외)
- 이벤트 프로토콜 (순서 고정, 각 이벤트는 `event:` 타입과 `data:` JSON):

| 이벤트 | 페이로드 | 의미 |
|---|---|---|
| `tool_call` | 도구명, 호출 사유 요약 | 어떤 도구를 왜 부르는지 |
| `tool_result` | 결과 요약 (행 수, 문서 수) | 도구 실행 결과 |
| `chart_spec` | 차트 명세 JSON | 아래 참조 |
| `answer_delta` | 텍스트 조각 | 답변 토큰 스트림 (반복) |
| `done` | 사용 토큰, 지연 요약 | 정상 종료 |
| `error` | 사유 코드, 메시지 | 실패 종료 (아래 참조) |

- 처리 흐름: 질문 → LLM이 도구 선택(이슈 13의 5종) → 실행 → 결과 종합 → 차트 선언 →
  답변 생성. 호출자 컨텍스트(브랜드, 역할)가 모든 도구 호출에 전달된다
- 답변에서 수치 근거(어느 조회 결과)와 문서 근거(어느 문서의 어느 부분)를 구분 표기
- 질의 1건 = trace 1건: 도구 호출, 문서 검색, 답변 생성이 하나의 trace에 하위 span으로

**chart_spec**
- 차트 유형 3종으로 시작: `bar`, `line`, `table`
- JSON Schema로 스펙을 코드에 고정: 유형, 축 매핑, 시리즈, 데이터 배열
- LLM이 생성한 spec이 스키마 검증에 실패하면 `table`로 폴백하고 실패를 로그에 기록
  (폴백 빈도가 높으면 프롬프트 개선의 지표가 된다)
- 프롬프트는 `prompts/` 디렉터리에서 파일로 버전 관리 — 코드와 같은 리뷰를 받고,
  변경 시 골든셋 평가(이슈 16)를 통과해야 머지

**실패 처리 (전부 "정직한 실패" — 대체 답변 생성 금지)**
- LLM 호출 최종 실패 (타임아웃, 재시도 소진) → `error` 이벤트 + 사유
- 도구가 권한 위반으로 차단 (이슈 13 Validator) → 차단 사유를 답변으로 스트리밍
  (이건 오류가 아니라 정상 동작 — 사용자가 이유를 알아야 한다)
- 도구 결과 0건 → "해당 데이터가 없다"를 답변으로 (지어내지 않음)
- 일일 비용 상한 초과 → 즉시 `error`, 운영 화면은 영향 없음

**프론트 (이슈 09 위에 어시스턴트 화면 추가)**
- fetch 스트림으로 SSE 파싱 (POST body가 필요하므로 EventSource 대신 fetch 사용)
- 진행 표시: 도구 호출 중(도구명 표시) → 차트 렌더 → 답변 타이핑 효과
- 차트 렌더러: 3종 지원, 근거 출처(수치/문서 구분) 표시
- 같은 conversationId로 후속 질문 입력 (대화 이어가기)
- 스트림 중단(네트워크 단절) → 부분 결과 유지 + 재시도 안내

## 예외 케이스

- [ ] LLM 최종 실패 → error 이벤트, 화면에 사유 표시, 추측 답변 없음
- [ ] 권한 침해 질의 → Validator 차단 사유가 답변으로 표시
- [ ] 데이터 0건 질의 ("2010년 캠페인") → "없음" 답변, 화면 정상
- [ ] chart_spec 스키마 위반 → table 폴백, 로그 기록
- [ ] 모호한 질문 ("누가 잘했어?") → 해석을 명시하고 답변 ("ROI 기준 상위로 해석했습니다")
      — 해석 명시 방침을 프롬프트에 규정하고 골든셋 케이스로 고정
- [ ] 클라이언트가 스트림 도중 연결 종료 → 서버가 진행 중 LLM 호출을 중단하고 자원 정리
- [ ] 같은 사용자의 연속 질의 (이전 질의 진행 중) → 이전 스트림 취소 후 새 질의 시작
- [ ] conversationId 없이 요청 → 새 대화로 시작 (오류 아님)
- [ ] 존재하지 않는 conversationId → 새 대화로 시작 + 응답에 새 ID
- [ ] 일일 비용 상한 초과 → error 이벤트, 사유 명시

## 테스트 케이스

**백엔드 단위 (LLM은 모의 클라이언트로 대체)**
- [ ] 이벤트 순서: tool_call → tool_result → chart_spec → answer_delta+ → done
- [ ] chart_spec 스키마 검증: 유효 spec 3종 통과, 필드 누락/유형 오타 spec → table 폴백
- [ ] 모의 LLM 실패 → error 이벤트, answer_delta 미발생
- [ ] 도구 0건 결과 → 답변에 "없음" 계열 표현 (모의 LLM 프롬프트에 신호 전달 확인)
- [ ] 대화 맥락: 같은 conversationId 2번째 질문의 프롬프트에 1번째 질문/답변 포함
- [ ] 클라이언트 중단 시뮬레이션 → LLM 호출 취소 확인

**통합 (실제 LLM, 시드 데이터 위에서 — 비용 관리를 위해 케이스 수 최소)**
- [ ] "이번 시즌 X브랜드 캠페인 ROI 상위 5명" → 이벤트 완주, chart_spec 유효,
      답변에 수치 근거 표기
- [ ] 권한 침해 질의 1건 → 차단 사유 스트리밍
- [ ] trace 1건에 도구 호출 span과 생성 span이 분리 기록
- [ ] 첫 토큰 지연과 질의 비용이 관측에 기록됨 (수치를 PR에 캡처)

**프론트 컴포넌트**
- [ ] SSE 파서: 이벤트 시퀀스 입력 → 상태 전이 (진행 표시 → 차트 → 답변)
- [ ] 차트 렌더러: bar/line/table 각 spec → 렌더, 잘못된 spec → table 폴백
- [ ] error 이벤트 → 에러 상태 렌더, 재시도 버튼
- [ ] 스트림 중단 → 부분 답변 유지

## 완료 조건

- [ ] 같은 질문이 Claude Desktop에서 같은 도구 경로로 동작 (이슈 13과 함께 확인)
