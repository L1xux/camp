# ADR-002: 빌드 툴체인과 버전 조합 (Gradle 8.14.5 + Spring Boot 3.5.16 + Spring AI 1.1.8)

- 상태: **채택** (2026-08-02)
- 상황: ADR-001에서 "Java 21 + Spring Boot 3.x + Spring AI"를 정했고, `docs/ENVIRONMENT.md`에는
  Gradle 9.6.1을 쓰기로 기록해 두었다. 이슈 #31 착수 시점에 실제 호환성을 확인한 결과
  **이 조합은 성립하지 않는다**는 것이 드러나 재결정이 필요했다.

## 확인한 사실 (2026-08-02, 공식 문서와 Maven Central 조회)

| 항목 | 확인 내용 |
|---|---|
| Spring Boot 3.5.x Gradle 플러그인 | "requires Gradle 7.x (7.6.4 or later) or 8.x (8.4 or later)" — Gradle 9 미지원 |
| Spring Boot 4.1.0 Gradle 플러그인 | "requires Gradle 8.x (8.14 or later) or 9.x", Java 17~26 |
| Spring AI 2.0.0 (GA) | `spring-boot-starter-*:4.1.0`을 참조 — Boot 4 기반 |
| Spring AI 1.1.8 | `spring-boot-starter:3.5.15`를 참조 — Boot 3.5 라인 |
| Gradle 최신 릴리스 | 9.6.1 |
| Spring Boot 3.5.x 최신 | 3.5.16 |

즉 선택지는 두 갈래였다. "Gradle 9.6.1 + Boot 3.5"라는 원래 계획은 어느 쪽도 아니다.

## 결정

**Java 21 + Gradle 8.14.5 + Spring Boot 3.5.16 + Spring AI 1.1.8**

## 이유

1. Spring Boot 3.5는 현재 기업 현장에서 가장 널리 운영되는 라인이다. 이 프로젝트는 5일 안에
   결재 워크플로우, 배치, MCP 도구, RAG까지 만들어야 하므로 막혔을 때 참고할 자료의 양이
   곧 진행 속도다. Boot 4는 메이저 릴리스라 축적된 사례가 아직 얇다.
2. Gradle 버전은 이 프로젝트에서 겉으로 드러나는 가치가 없다. 반면 Boot 메이저 버전은
   Oracle 드라이버, 마이그레이션 도구, Spring AI까지 연쇄로 호환을 확인해야 하는 변수다.
   불확실성을 어디에 둘지 고른다면 Gradle 쪽이 싸다.
3. Spring AI 1.1.8은 Boot 3.5 라인의 최신이며 MCP 서버 지원을 포함한다. 이 프로젝트가
   필요로 하는 기능은 1.1.x에 이미 있다.

## 버린 대안

**Spring Boot 4.1.0 + Spring AI 2.0.0 + Gradle 9.6.1** — 전부 현재 GA이고 서로 정렬된 조합이라
버전 고민이 없다. Spring AI 2.0이 앞으로 기능이 추가되는 라인이라는 것도 장점이다.
기각 근거: 메이저 신규 버전이라 Oracle JDBC, 마이그레이션 도구, 관측 라이브러리와의 호환을
각각 다시 확인해야 하고, 5일 스프린트에서 그 확인 비용과 막혔을 때의 자료 부족이
얻는 것보다 크다고 판단했다.

## 트레이드오프

- Gradle을 최신(9.6.1)에서 8.14.5로 내렸다. `docs/ENVIRONMENT.md`의 기록을 수정했다.
- Spring AI 1.1.x는 언젠가 유지보수 라인이 된다. 2.0으로 올릴 때 Boot 4 이관이 함께 필요하며,
  그 시점의 비용은 지금 감수한 것보다 클 수 있다.
- ADR-001에 기록된 버전(Boot 3.5.3, Spring AI 1.0.0)은 조사 시점의 값이었고 이 ADR이 대체한다.
  ADR-001의 스택 **선정**(Java/Spring, Spring AI, Oracle, 멀티모듈 모놀리스)은 그대로 유효하다.
